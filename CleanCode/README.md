# 🧼 Clean Code Made Simple
---

## 🧱 1. SOLID Principles

SOLID is a set of five principles for designing robust and flexible software.

### 🔹 S — Single Responsibility Principle (SRP)
> A class should have only one reason to change.

Each component should focus on a single responsibility.  
This keeps code easier to understand, test, and maintain.

---

### 🔹 O — Open/Closed Principle (OCP)
> Open for extension, closed for modification.

You should be able to extend behavior without changing existing code.  
This reduces the risk of breaking stable functionality.

---

### 🔹 L — Liskov Substitution Principle (LSP)
> Subtypes must be substitutable for their base types.

Derived classes should behave consistently with their base classes.  
Violating this leads to unexpected bugs and unstable systems.

---

### 🔹 I — Interface Segregation Principle (ISP)
> Don’t force clients to depend on methods they don’t use.

Keep interfaces small and focused.  
Large, general-purpose interfaces create unnecessary complexity.

---

### 🔹 D — Dependency Inversion Principle (DIP)
> Depend on abstractions, not concrete implementations.

High-level modules should not depend on low-level details.  
This improves flexibility and makes systems easier to evolve.

---

## ✂️ 2. KISS — Keep It Simple, Stupid

> The simplest solution is usually the best one.

Avoid unnecessary complexity.  
Simple code is easier to read, debug, and maintain.

---

## 🔁 3. DRY — Don’t Repeat Yourself

> Avoid duplicating logic.

Duplicated code increases maintenance cost and risk of inconsistency.  
Centralizing logic improves clarity and reduces errors.

---

## 🧯 4. YAGNI — You Aren’t Gonna Need It

> Don’t build something until it is necessary.

Focus only on current requirements.  
Building unused features wastes time and adds unnecessary complexity.

---

## 🔁 Recap

| Principle | Purpose |
|----------|--------|
| **SOLID** | Build maintainable and flexible systems |
| **KISS**  | Keep things simple and clear |
| **DRY**   | Reduce duplication |
| **YAGNI** | Avoid unnecessary features |

---

## ✨ Closing

> "Code is read more often than it is written."

Write code for humans first — machines second.
